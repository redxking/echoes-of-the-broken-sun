# Echoes audio listening review

Read `Docs/AudioDirection.md`, the audio rules in `Docs/Archive/DevelopmentBible.md`, Track C in `Docs/GameCompletionDirective.md`, `Docs/Archive/ProjectLedger.md`, `Docs/Archive/AssetRegister.md`, the package identity, and `../WorkstreamControl/ACTIVE_LANES.md`. Use an actual audio output/listening path and live rendered gameplay; waveforms, logs, or screenshots alone do not prove player-perceived audibility. If audio cannot be heard through the available interface, stop and request a human/listening tool.

Sample title, briefing, ambience, selection/command acknowledgement, rejected action, combat concurrency, Well, menu, voice/subtitle synchronization, cinematics, result, mute/volume categories, reduced dynamic range, and pause. Record output device, level/settings, route, timestamp, observed cue, masking/dropout/latency, subtitle relation, and defects. Check that every claimed setting changes behavior.

Keep loudness, true-peak, and mix compliance as separate measured gates. Agent listening is not broad human-audience or owner acceptance; do not add or approve voices/assets without registered rights/provenance.

Before any live listening session, read `../WorkstreamControl/HEAVY_RUN_LOCK.md`, acquire a current detailed lease, and explicitly release it. Stop if no current specific lease exists. Route package identity via `echoes-package-provenance`, measurement via `echoes-performance-profiling`, and owner testing via `echoes-human-acceptance-session`.
